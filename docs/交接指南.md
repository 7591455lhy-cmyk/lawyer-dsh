# lawyer-dsh 交接指南（接手同事必读）

> 本文档面向从交接包恢复开发环境的同事。项目全貌与铁律见随包的 `CODEBUDDY.md`，
> 完整设计见 `lawyer-dsh-开发方案.md`。`CODEBUDDY.md` 里的 `D:\codes` 是原开发机目录，请按你自己的目录理解。

## 1. 交接包里有什么 / 刻意不带什么

| 内容 | 说明 |
|---|---|
| `lawyer-dsh/` | 项目源码：`plugins/`（三个插件：lawyer-sidebar / lawyer-tools / lawyer-wizard，含 src 与已构建的 lib）、`skills/`（律师技能）、`profiles/lawyer/`（agent preset）、`docs/`、`packaging/`（Electron 壳源码与打包脚本）、`debug-web.cmd`（一键调试）、`START-HERE.cmd`（一键恢复） |
| `deepseek-harness/` | dsh 0.1.1-rc.2 源码 + 已构建产物（各包 `lib/`）。本地调试宿主与 API 参考，**只读，不要修改** |
| `CODEBUDDY.md` | 项目约定速览（插件铁律、常用命令） |

**刻意不带**（全部可重建）：两侧 `node_modules`、`packaging/dist`（NSIS 安装包产物）、`packaging/runtime`（打包预组装产物）、日志与各类缓存。

**不带也不该带**：任何 API key。

## 2. 前置软件

- Windows 10/11，PowerShell 5.1+
- Node.js **22.19+ 或 24+**（dsh engines 要求 `^22.19 || >=24`）：https://nodejs.org
- pnpm **11.7.0**（harness 用 packageManager 锁定）：`npm install -g pnpm@11.7.0`

## 3. 恢复步骤（推荐：一键引导）

1. 解压 zip，保证目录并排（盘符与父目录名不限，但两个目录必须在**同一父目录**下——所有脚本按此自动探测）：
   ```
   <任意父目录>\
   ├─ deepseek-harness\
   └─ lawyer-dsh\
   ```
2. 双击 `lawyer-dsh\START-HERE.cmd`，它会依次完成：
   自检 Node/pnpm/harness → harness 下 `pnpm install`（需联网，几分钟）→ 构建三个插件 → 检查 `YUANDIAN_API_KEY` → 询问是否启动调试
3. 首次启动后浏览器打开 http://127.0.0.1:3080 并 **Ctrl+F5 强刷**；
   在 Web 界面 **Settings → Models** 填入**你自己的** DeepSeek API key。

## 4. 恢复步骤（手动，与上面等价）

```powershell
# ① harness 依赖（一次性，需联网）
cd <你的父目录>\deepseek-harness
pnpm install
# 交接包已带 harness 的已构建产物（各包 lib/）；若遇产物缺失/异常可兜底重建：
# pnpm run build

# ② 构建三个插件（每次改 src 后都必须重建，否则浏览器加载旧 client.js）
cd <你的父目录>\lawyer-dsh\plugins\lawyer-sidebar
powershell -ExecutionPolicy Bypass -File build.ps1
# lawyer-tools、lawyer-wizard 同理。
# build.ps1 自动探测并排的 deepseek-harness；布局不同可 -Harness <路径> 显式指定

# ③ 一键调试（装插件进 web profile + 部署 preset + 启动 dsh web）
cd <你的父目录>\lawyer-dsh
.\debug-web.cmd
# 日志: lawyer-dsh\.dsh-web.log；浏览器: http://127.0.0.1:3080（Ctrl+F5 强刷）
```

## 5. 日常开发循环

| 改了什么 | 要做什么 |
|---|---|
| 插件 `src/`（ts/tsx） | 对应 `plugins/<包>/build.ps1` 重建 → 重跑 `debug-web.cmd`（内部先 remove 再 add，确保取到新产物） |
| `profiles/lawyer/`（preset） | 重跑 `debug-web.cmd`（幂等覆盖到 `%USERPROFILE%\.dsh\.agent-presets\lawyer`） |
| `skills/` | 直接重跑，无需构建（skillsDir 指向源码目录） |
| 出安装包 | `packaging/` 下：`npm install` → `npm run prepare-runtime`（组装 runtime，需联网下载 Node 与 dsh）→ `npm run dist`（产物 `packaging\dist\LawyerWorkbench-Setup-<版本>.exe`）；`npm run dev:launch` 验证开发模式 |
| 出「无演示数据」安装包 | 先在 `plugins/lawyer-sidebar` 跑 `powershell -File build.ps1 -NoDemo`（去掉三入口的「载入演示数据」按钮与演示回放链路，client.js 约从 527KB 降到 304KB），再按上面三步 prepare-runtime → dist。产物与带演示版本同名 `摸鱼工作站-Setup-<版本>.exe`，出包前记得清旧 `dist`（`powershell -File scripts/_clean-dist.ps1`，否则 electron-builder 删旧目录会撞批量删除保护） |

## 6. 凭据（私下交接，绝不进代码/压缩包）

| 凭据 | 用途 | 缺失时的行为 |
|---|---|---|
| `YUANDIAN_API_KEY` | 元典 MCP（法规/案例检索），https://open.chineselaw.com 注册获取 | 法规检索工具不可用；合同审核按技能内置降级指引继续 |
| DeepSeek 模型 key | dsh 模型调用；Web 界面 Settings → Models 填写（或环境变量 `DEEPSEEK_API_KEY`） | 无法发起会话 |

两个 Key 都在应用内有引导（M8.6），不必再手工设环境变量：

- **DeepSeek 模型 key**：首次启动先弹「第 1 步：准备一个 DeepSeek API Key」——
  引导页给出开放平台注册 / 创建 Key / 充值三个可点链接（系统浏览器打开），
  点「去填写」后进入 dsh 官方的 Key 输入框。
- **元典 MCP key**：首次点右侧任一功能入口时弹「接上元典法规检索（可选）」，
  直接粘贴保存即生效（写 `%USERPROFILE%\.dsh\lawyer-secrets.json` 并注入进程，
  **不用重启**）；不配也能继续用，只是法条与类案要标注「需验证」。之后可从
  侧栏底部「元典法规检索：… ›」随时改配置。

手工设置仍然有效且优先级更高：`setx YUANDIAN_API_KEY "..."`（注意 setx 后
需新开终端生效）——引导里保存的 Key 只在系统环境变量为空时生效。

## 7. 已知坑位清单

- **目录布局是硬约束**：`deepseek-harness` 与 `lawyer-dsh` 必须并排。布局特殊时设环境变量 `DSH_HARNESS_ROOT` 指向 harness 根，或给 `build.ps1` 传 `-Harness <路径>`。
- dsh 用户数据在 `%USERPROFILE%\.dsh`（web profile 插件、agent preset 部署目标）；Electron 打包版数据隔离在 `%APPDATA%\lawyer-workbench`。
- **3080 端口**：`debug-web.cmd` 启动前会按端口杀旧进程（旧进程持有 profile 文件句柄），不要同时开两个调试实例。
- pnpm 对 `file:` 依赖的"跳过更新"行为：改了插件却忘了 `build.ps1` 重建 → 浏览器加载的还是旧 `client.js`。
- `pdfkit-py`（PDF 工具箱）是**技能市场的第三方技能**，不随本仓库分发：合同审核表单里的「输入预处理」勾选它、三个技能的 PDF 处理章节也提到它，本机没装时相关能力不可用，其余功能不受影响。需要时从技能市场自行安装到 `skills/`。
- 开发任何 dsh 插件前先读 dsh 源码（`deepseek-harness/docs/development.md`、`vendor/cordis/src/`、`packages/core/tools/src/`），**禁止凭记忆编造 API**；插件铁律见 `CODEBUDDY.md`。
